## Acceptance Criteria Status

- One logical Stripe payment per order: implemented with `(order_id, provider)` uniqueness and transaction-scoped advisory reservation.
- Deterministic Stripe idempotency: implemented as `keycore:payment-intent:create:<OrderId>:v1`.
- No DB transaction across Stripe HTTP: implemented by reserving locally before invoking the provider port.
- No persisted `client_secret`: implemented and tested.
- Raw-body webhook signature verification: implemented through Stripe SDK `constructEvent`.
- Supported webhook events: implemented for succeeded, failed, processing and canceled.
- Success validation before capture: implemented for mapping, amount, currency and metadata order relationship.
- Failure, canceled and processing are not procurement eligible: implemented and tested.
- Success does not approve risk or start procurement: implemented and tested.
- Test-mode only configuration: implemented and tested.
- Reversible migration: implemented with migration 010 up/down.
