## Database And Persistence

No PostgreSQL migration was added. The existing customer account order
projection already carries safe invoice metadata and structured activation
metadata. KS-08-06 adds explicit service and transport boundaries over that
projection rather than a new durable schema.

## Implementation Notes

- Added `CustomerInvoiceAccessService` for authenticated owned-order invoice
  metadata reads.
- Added `CustomerActivationInstructionsService` for curated activation
  instruction resolution from structured account metadata.
- Added default curated `STEAM_ACTIVATION_CODE` instructions.
- Added registry validation for unsafe instruction codes, oversized text,
  control characters, HTML-like text, unsafe help URLs and untrusted help
  hosts.
- Hardened invoice customer projection to omit malformed references, invalid
  timestamps and non-available invoice artifact metadata.
- Hardened activation registry construction to fail on duplicate keys,
  defensively copy validated entries and reject help URLs with userinfo,
  deceptive hosts or unusual ports.
- Added explicit transport read handlers:
  - `getInvoiceMetadata`;
  - `getActivationInstructions`.
- Transport reads reject body fields, query parameters and caller-supplied
  invoice/platform/instruction authority fields.
- Both reads use `private, no-store` response headers.
- Wrong-owner, unknown and legacy/unclaimed orders remain indistinguishable at
  the customer boundary.
