## Migrations

Added reversible migration `007_pricing_margin_foundation`.

It creates durable global pricing policies, product pricing overrides and product price snapshots. Snapshot writes are idempotent by product, offer and source fingerprint.

## Pricing Policy Version

`pricing-policy-v1`

## Money Implementation

All pricing calculations use existing `Money` values with `bigint` integer minor units. No floating point arithmetic is used for business-critical money calculations.

## Global Pricing Policy Model

The global policy is durable, active/versioned and supports enabled state, markup basis points, optional target margin basis points, fixed markup, minimum profit, minimum sell price, rounding, quote TTL, actor and reason metadata.

## Product Override And Manual Price Model

Product overrides selectively replace global fields and inherit unspecified global values. Manual sell price is distinct from policy target fields and has its own version. Manual price remains subject to hard safety checks.

PR #12 hardening makes the manual sell-price invariant explicit across the domain, in-memory repository, PostgreSQL repository, PostgreSQL constraint and hydration boundary: when a manual price exists, its amount must be greater than zero and amount/currency must be stored together. `0.00` is invalid configuration rather than a valid unsafe quote. Clearing a manual price still stores no amount, no currency and no manual price version.

Follow-up CI hardening corrected the PostgreSQL tuple invariant to be fully atomic. Valid persisted manual-price states are now exactly either all manual-price fields null, or `manual_sell_price_minor IS NOT NULL AND manual_sell_price_minor > 0`, `manual_sell_price_currency IS NOT NULL`, and `manual_price_version IS NOT NULL AND manual_price_version > 0`. CI had previously accepted the partial tuple with `manual_sell_price_currency = 'EUR'` but no amount or version because SQL `CHECK` expressions treat `NULL` as pass unless the predicate is written explicitly.

## Precedence And Hard Safety

Hard configuration, currency, fee, tax, stale-input and minimum-profit constraints are evaluated before customer price publication. Manual price beats target formula only after those hard constraints pass. Product override fields beat global policy fields.

## Fee, Tax And FX Boundaries

Known fixed and percentage supplier fees are included. Unknown required fees block pricing. Tax is delegated to `TaxPolicyPort`; unknown treatment returns review-required behavior. Cross-currency pricing requires a trusted versioned `ExchangeRatePort` quote; missing or stale FX blocks.

## Rounding And Minimum Profit

Rounding supports minor-unit behavior and configured psychological endings. Rounding is upward-only relative to the configured ending and cannot reduce prices below minimum profit or minimum sell price.

## Multi-Supplier Selection

Pricing evaluates multiple eligible offers independently, excludes blocked quotes and deterministically selects the lowest safe sell price with `OfferId` tie-breaking. The storefront-facing provider returns only `Money | null` and does not expose supplier identity or supplier cost.

## Persistence

PostgreSQL repositories persist active policy, product overrides and price snapshots. Manual update methods use optimistic versioning and throw `PricingConfigurationConflictError` on stale updates.

The hardening review also aligned pricing configuration invariants between TypeScript and migration `007`: record versions and manual price versions must be positive, quote TTL must be positive when configured, markup basis points must be non-negative, target margin basis points must be greater than zero and less than `10000`, and configured money amounts other than manual sell price remain non-negative.

CI run #47 also exposed a catalog-search integration-test race in the pre-existing GIN-index assertion. `pg_indexes.indexdef` can resolve relation OIDs while another parallel isolated schema is being dropped. The assertion now verifies `catalog_search_documents_text_idx` for the current schema through `pg_class`, `pg_namespace`, `pg_index` and `pg_am`, preserving the GIN-index check without relying on that view's index definition reconstruction. The shared `PostgresTestDatabase` helper now serializes queries per `pg.Client` instance to avoid concurrent calls on one client and address the pg@9 deprecation warning.

## Admin Command Foundation

`PricingService` exposes command-style methods for global policy updates and product override/manual price updates with actor, reason, correlation ID, audit and storefront re-evaluation hooks. No admin UI or public admin API was built.

## 50k Scale Result

The focused pricing unit test evaluates 50,000 synthetic offer pricing inputs with no external HTTP and verifies every quoted result remains above the hard minimum profit floor. The local run completed inside the normal unit-test execution.
