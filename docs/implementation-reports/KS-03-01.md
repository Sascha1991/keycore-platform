## SupplierPort Changes

The existing SupplierPort was refined for a supplier-neutral deficiency: catalog/product/offer returns now expose normalized supplier records with both supplier-side references and explicit mapped KeyCore IDs. This preserves the recognizable existing concepts while preventing supplier IDs from being confused with internal IDs.

Additional capability flags were added for full catalog, price lookup, region evidence, purchase, and health/rate-limit information.

## Capability Model

Capabilities describe behavior only and contain no credentials, endpoint URLs, or transport configuration. Unsupported optional capabilities fail explicitly with `UNSUPPORTED_CAPABILITY`.

## Normalization Model

- `NormalizedSupplierProduct` wraps supplier identity, supplier product ID, mapped product summary, lifecycle and changed timestamp.
- `NormalizedSupplierOffer` wraps supplier identity, supplier offer ID, supplier product relation, mapped offer summary, region evidence, captured timestamp and safe metadata.

## SupplierRegistry Design

`SupplierRegistry` stores adapter references, prevents duplicate `SupplierId` registration, resolves known suppliers, fails unknown lookups with `NOT_FOUND`, and lists identities/capabilities deterministically.

## MockSupplier Behavior

MockSupplier is offline and deterministic. It supports configured synthetic products/offers, full and delta catalog, lookup, price, region evidence, purchase scenarios, reconciliation, key-handle retrieval, refund claims, health/rate-limit metadata and deterministic fault injection.

## Error Taxonomy

The supplier-neutral taxonomy includes authentication, authorization, rate limit, timeout, transient, invalid response, not found, out of stock, rejected, conflict, unsupported capability and unknown categories. Error messages are sanitized and tests assert no credential-like content leaks.

## Idempotency Model

Same idempotency reference plus same semantic purchase request returns the same receipt. Conflicting reuse fails with `CONFLICT`. MockSupplier does not create duplicate supplier purchases for repeats.

## Reconciliation Model

Synthetic reconciliation maps accepted and delayed purchases to resolved results, ambiguous purchases to still ambiguous, and failed/unavailable paths to manual review.

## Fault Injection Model

Faults are opt-in by operation and deterministic:

- `TIMEOUT`
- `RATE_LIMITED`
- `TRANSIENT_ERROR`
- `TERMINAL_ERROR`
- `MALFORMED_RESPONSE_SIMULATION`

## Contract Test Architecture

`runSupplierContractTests` accepts a supplier factory and fixture references. The suite checks identity, contract version, capability consistency, pagination, empty catalog behavior, lookup, money, availability, region evidence, idempotency, reconciliation, key/refund capability behavior, health/rate limits, and secret safety.
