## Architecture

- HTTP/framework decision: no new framework; transport-neutral handler first.
- Resource identifier: KeyCore order UUID plus fulfillment UUID; no supplier
  identifiers accepted.
- Session transport: secure cookie policy contract, resolved through KS-07-07
  session service.
- Principal resolution: request credential becomes a principal only through
  `CustomerAuthenticationService.resolveSession`.
- Object authorization: KS-07-05 delivery service and KS-07-06 persisted
  authorization verify fulfillment/order/customer ownership.
- Delivery capability: retained as required defense in depth; returned only
  once from prepare, hash-only persisted, consumed atomically.
- CSRF: HMAC double-submit policy bound to the session credential hash.
- Origin/CORS: configured allow-list, no wildcard for credentialed delivery.
- Rate limiting: in-memory port by hashed session/resource/IP dimensions;
  production distributed limiter not implemented.
- Response/cache: JSON responses with `Cache-Control: no-store`,
  `Pragma: no-cache`, `X-Content-Type-Options: nosniff` and
  `Referrer-Policy: no-referrer`.
- Secret lifetime: plaintext exists only inside the KS-07-05 delivery engine
  and delivery port boundary, then is zeroed by existing delivery service.
- Replay/concurrency: one-time capability claim is authoritative; ten
  concurrent synthetic requests produce one delivery.
- Session revocation race: handler resolves a current session before crossing
  the delivery boundary; revoked/expired/invalid sessions are denied before
  decrypt.
- Delivery acknowledgement: HTTP success is not human acknowledgement. No human
  acknowledgement semantics were added.
- Audit: safe fulfillment events only; no product key, session credential,
  capability, capability hash or CSRF token in audit metadata.
- Safe inspect: no new inspect command; existing customer/fulfillment/delivery
  inspection remains sufficient.
- Migration: no migration 018. Existing KS-07-05/06/07 persistence is
  sufficient.
