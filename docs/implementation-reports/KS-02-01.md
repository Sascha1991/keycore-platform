## Schema Overview

PostgreSQL is the durable system of record for KeyCore platform state. WordPress/WooCommerce tables are not used as KeyCore's primary persistence layer.

The initial schema separates supplier-side identifiers from KeyCore internal UUIDs, keeps order-line UUIDs as future idempotency roots, stores monetary amounts as integer minor units plus currency, stores region decisions with approved decision constraints, keeps encrypted key records ciphertext-only, and stores audit events in append-oriented form with JSONB metadata guardrails.

## Migration Technology Selected and Why

Selected:

- Plain SQL migrations with paired `.up.sql` and `.down.sql` files.
- A small TypeScript runner in `infra/postgres/migrate.ts`.
- `pg@8.23.0` as the PostgreSQL client.

Reason:

- Plain SQL keeps constraints, foreign keys, indexes, and PostgreSQL-specific checks explicit and reviewable.
- Paired down migrations satisfy the reversible migration requirement.
- A TypeScript runner fits the existing Node.js/TypeScript architecture without introducing a large framework.

## Important Constraints and Indexes

- Supplier code unique.
- Supplier product IDs unique per supplier.
- Supplier offer IDs unique per supplier.
- Internal offer maps uniquely to supplier offer.
- Commerce order external references unique.
- Commerce order-line UUID primary key is generated internally.
- Payment provider event IDs unique per provider.
- Payment idempotency unique per order line.
- Procurement client references unique per supplier.
- Procurement purchase references unique per supplier.
- Refund provider event IDs unique per provider.
- Refund idempotency references unique per order line.
- Idempotency records unique by scope/key and scope/provider event.
- Outbox event deduplication key unique.
- Germany compatibility decisions constrained to `ALLOWED`, `BLOCKED`, `REVIEW_REQUIRED`, `DISABLED`.
- Money fields use `BIGINT amount_minor` plus `CHAR(3) currency` and non-negative checks.
- Audit metadata rejects product-key, plaintext-key, raw-key, decrypted-key, unencrypted-key, API-secret, password, and payment-credential field names.
- Encrypted key records contain ciphertext, nonce, authentication tag, wrapped DEK, algorithm, key version, ownership, and timestamps only.

## CI Test Correction

The supplier product uniqueness integration test was corrected after GitHub Actions exposed that it was inserting a hard-coded `supplier_product_id` instead of reusing the fixture's generated supplier-side product reference. The fixture now returns `supplierProductExternalId`, and the test attempts a second `supplier_products` insert with the same `supplier_id` and same supplier-side product ID but a different title. This genuinely verifies the intended `(supplier_id, supplier_product_id)` unique constraint without changing the migration.
