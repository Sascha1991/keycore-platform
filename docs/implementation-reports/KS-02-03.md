## Cryptographic Algorithm

- Product-key encryption: `AES-256-GCM-v1`.
- DEK length: 256 bits.
- Nonce length: 96 bits.
- Randomness: Node.js built-in cryptographic randomness.
- Authentication: AES-GCM authentication tag verified before plaintext is returned.

No custom cryptography or external cryptography dependency was added.

## Encryption Design

Store flow:

1. Accept short-lived product-key bytes in process memory.
2. Generate a unique random DEK.
3. Generate a unique random nonce.
4. Encrypt product-key bytes with AES-256-GCM.
5. Wrap the DEK through `KeyManagementProvider`.
6. Store only ciphertext, nonce, authentication tag, wrapped DEK, algorithm, key version, and ownership metadata.
7. Zero-fill DEK buffers as soon as practical.

Reveal flow:

1. Require explicit `KeyAccessContext`.
2. Ask `KeyAccessAuthorizationPort` for a reveal decision.
3. Deny before decrypting when authorization is not allowed.
4. Load encrypted material.
5. Unwrap DEK through `KeyManagementProvider`.
6. Authenticated decrypt.
7. Return plaintext only to the authorized caller.

## KeyManagementProvider Design

The provider port supports:

- active master-key version;
- `wrapDataKey`;
- `unwrapDataKey`;
- key-version metadata;
- rotation-compatible rewrap.

Production providers such as AWS KMS, Google Cloud KMS, Azure Key Vault, and HashiCorp Vault remain future adapters.

## Development Provider Behavior

The development/test provider:

- accepts master-key material only through configuration;
- requires 32 bytes of base64-decoded local material;
- fails closed when material is missing or invalid;
- refuses `production` environment mode;
- uses AES-256-GCM to wrap DEKs for local and CI tests.

`.env.example` contains only a placeholder for `KEYCORE_DEV_MASTER_KEY`.

## PostgreSQL Repository Design

`PostgresEncryptedKeyRepository` uses the existing `encrypted_key_records` schema. It accepts `EncryptedKeyMaterial`, not plaintext product-key strings. The schema already contains ciphertext, nonce, authentication tag, wrapped DEK, algorithm, key version, owning order-line ID, and rotation/retirement timestamps, so no migration was required.

## Authorization Boundary

`ProductKeyVaultService` requires a `KeyAccessContext` and delegates reveal decisions to `KeyAccessAuthorizationPort`. The vault does not assume that knowing an order-line ID is sufficient authorization. WooCommerce session and customer portal authorization remain deferred to KS-08.

## Rotation Design

Rewrap support unwraps the existing DEK in memory and rewraps it with a new active provider/master-key version. Product-key ciphertext is unchanged during master-key rotation preparation.

## Audit Integration

Secret-safe audit events are supported for:

- `KEY_STORED`
- `KEY_REVEALED`
- `KEY_ACCESS_DENIED`
- `KEY_REWRAPPED`
- `KEY_RETIRED`

Audit metadata includes only non-secret references such as order-line ID and key version. It does not contain plaintext, ciphertext, nonce, authentication tag, DEK, wrapped DEK, or master-key material.

## Tests Added

- AES-GCM authenticated-encryption round trip.
- Same secret stored twice creates different ciphertext, nonce, and wrapping material.
- Tampered ciphertext fails.
- Tampered authentication tag fails.
- Tampered nonce fails.
- Tampered wrapped DEK fails.
- Authorized reveal succeeds.
- Unauthorized reveal is denied.
- Unauthorized reveal does not call DEK unwrap.
- Rewrap changes wrapped DEK and key version without changing product-key ciphertext.
- Missing development master key fails closed.
- Development provider refuses production mode.
- Development provider wrap/unwrap and tamper behavior.
- PostgreSQL encrypted-key record stores no canary plaintext.
- PostgreSQL key-version metadata persistence.
- PostgreSQL duplicate order-line key record rejection.
- Canary plaintext does not leak into logs, exceptions, audit events, queue/outbox metadata, serialized encrypted metadata, or PostgreSQL raw material checks.
- Core dependency boundary rejects PostgreSQL, Redis, supplier, payment, and cloud-KMS client imports.

- audit events;
