# KS-11-03 Implementation Report

## Summary

Implemented a release-blocking PostgreSQL catalog scale suite covering 50,000
paged deterministic synthetic products, 60,000 baseline offers, changed refresh,
exact replay, publication, Germany eligibility, database invariants and safe CI
evidence.

## Architecture Changes

- Added an optional bounded page-upsert contract to `CatalogSyncRepository`.
- Added transactional JSON-recordset page persistence to the existing
  `PostgresCatalogSyncRepository`; other repositories retain their existing
  record fallback.
- Preserved internal ProductId identity during supplier-product refresh and
  avoided duplicate unchanged evidence/decision/price snapshots.
- Made repeated blocked/unpublished storefront evaluation a side-effect-free
  `NO_OP`.
- Removed a measured publication N+1 bottleneck by page-preloading scale
  snapshots/prices/publications and reducing PostgreSQL publication persistence
  to one atomic upsert within a bounded 500-product transaction. Existing
  mapping-conflict behavior and unique constraints remain fail-closed.
- Added reversible migration 027 with measured missing unique snapshot indexes
  for evidence `(offer_id, source_evidence_version, captured_at)` and decisions
  `(offer_id, region_evidence_id, decision, reason_code, policy_version)`. These
  formalize existing deduplication identities; no business decision changed.
- Made `PostgresTestDatabase` transaction ownership exclusive and callback
  scoped, preventing queries from interleaving between `BEGIN` and `COMMIT`.
- Reworked the scale suite into one guarded baseline/refresh/replay setup
  journey. Ten scenario assertions run only after all dependent phases finish.
- Added omission-first aggregate profiling for schema setup, catalog sync,
  publication, stale deactivation and representative pages 1/10/25/50/75/100.

## Dataset And Expected Counts

- Baseline source: 50,000 products, 60,000 offers, 100 pages of 500.
- Refresh source: 50,000 active products and 55,500 active offers.
- Refresh changes: 100 new products, 610 new offers, 100 stale products and
  5,110 stale offers, plus deterministic title, price, availability and region
  changes.
- Final durable identities: 50,100 products and 60,610 offers.
- Exact replay must leave products, offers, publications and snapshot counts
  unchanged and make no remote storefront mutation.

## Performance

Each baseline, refresh and replay pass has a five-minute hard ceiling; the CI
step has a 20-minute ceiling. Local PostgreSQL execution was unavailable because
the workstation has no Docker/PostgreSQL runtime. Quality Gates #156 supplied
the authoritative successful measurements:

| Journey  | Catalog sync | Publication | Total     |
| -------- | ------------ | ----------- | --------- |
| Baseline | 33,166 ms    | 39,244 ms   | 72,410 ms |
| Refresh  | 21,428 ms    | 9,397 ms    | 30,825 ms |
| Replay   | 19,735 ms    | 8,722 ms    | 28,457 ms |

The three journey totals sum to 131,692 ms. The complete scale command,
including schema setup and ten assertions, completed in 136.49 seconds. No
300,000 ms journey target or dataset count was changed.

The first branch CI run exposed the original per-product scale snapshot path as
an actual N+1 defect: baseline exceeded the five-minute test limit and Vitest's
non-cancelling timeout caused dependent scenarios to cascade. The focused fix
uses bounded 500-product publication pages and the repository's database
constraints rather than raising either performance threshold.

The second CI run verified all ordinary PostgreSQL and mapping-conflict tests
but exposed per-row autocommit as the remaining scale cost and reached the
20-minute step limit. Publication writes now share the already documented
500-product page transaction; no threshold was changed.

Quality Gates #147 then proved the catalog bottleneck was independent of
publication: baseline reached only page 31 before the unchanged five-minute
limit. The growing `region_evidence` table had no index matching the exact
snapshot identity used by every page's `NOT EXISTS` check. Timeout continuation
also launched dependent stateful tests against the same single-client test
database, producing invalid nested transaction warnings and partial-state
cascades. Migration 027 and exclusive transaction ownership addressed those
root causes; the successful final timings are recorded above.

Quality Gates #148 completed all 100 baseline pages after migration 027 and
reduced baseline sync to 301,252 ms, narrowly above the unchanged 300,000 ms
release gate. The next correction removes repeated supplier identity upserts,
deduplicates page-payload serialization and makes the evidence ID available
from the composite index. Safe aggregate diagnostics are now archived even when
a phase limit fails. Transaction warnings in #148 occurred during older
parallel PostgreSQL test wrappers before the dedicated scale command; the scale
PID emitted none.

Quality Gates #149 archived aggregate diagnostics at the same boundary:
baseline sync was 300,157 ms; representative page persistence grew from 949 ms
on page 1 to 6,862 ms on page 10 and 16,682 ms on page 25, then fell to roughly
320 ms by pages 50/75/100. This proves an early statistics-dependent correlated
dedupe plan rather than steady catalog-size cost. Migration 027 now makes the
natural evidence snapshot identity unique and persistence uses
`ON CONFLICT DO NOTHING`, removing that plan choice while strengthening replay
and concurrent-writer idempotency.

Quality Gates #151 isolated the remaining cost precisely: baseline sync was
318,990 ms, of which `region_decision` consumed 288,677 ms. The other page SQL,
run/checkpoint work and transaction boundaries together consumed roughly 30
seconds; 100 `BEGIN` calls totaled 35 ms and 100 `COMMIT` calls 207 ms. The
decision identity is therefore now enforced by the second migration-027 unique
index and persisted with `ON CONFLICT DO NOTHING`.

Quality Gates #152 showed that conflict handling alone did not constrain the
planner's evidence-join order: `region_decision` still consumed 269,684 ms of a
296,234 ms baseline sync. Evidence resolution is now an explicit, unique
per-offer lateral lookup backed by the migration-027 evidence index. SCALE-009
explains this representative lookup shape; #156 subsequently completed the
full journey.

Quality Gates #156 completed the journey and all SCALE-001 through SCALE-010
assertions. SCALE-009 now separates invariant proof from planner choice: the
unique decision identity and duplicate rejection remain mandatory, while the
representative plan must structurally prove bounded index access with all
expected predicates. PostgreSQL's valid #155 selection of
`idx_region_decisions_offer` is accepted alongside
`region_decisions_snapshot_identity_idx`; no planner setting or production
query was changed.

The #156 ordinary parallel PostgreSQL regression emitted transaction-state
warnings at 16:34:13-16:34:15 UTC and concurrent `client.query()` warnings no
later than 16:34:46 UTC. The dedicated scale command ran from 16:34:48 through
16:37:05 UTC without either warning. The warnings therefore originate outside
the isolated KS-11-03 execution and were not suppressed or broadened into this
task.
