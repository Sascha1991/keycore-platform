## Architecture

- Service: `DisputeEvidenceService`.
- Schema/policy version: `KS_DISPUTE_EVIDENCE_V1`.
- Mandatory sections: `ORDER`, `PAYMENT`.
- Optional sections: customer account, ownership, guest claim, fraud, velocity,
  procurement, fulfillment, delivery, invoice and audit summary.
- Fingerprint: deterministic SHA-256 over exact order id, schema version and
  canonical evidence sections.
- Idempotency: same order/schema/fingerprint reuses the existing snapshot;
  changed authoritative facts create a new version.
- Authorities: finalization and export default to fail-closed denial.
- Export: provider-neutral structured payload bound to exact order id and
  snapshot id.

## Persistence

Migration 022: YES.

Table:

- `dispute_evidence_snapshots`

Constraints and indexes:

- FK to `keycore_orders`;
- state constrained to `DRAFT`, `FINALIZED`, `INVALIDATED`;
- schema and policy version constrained to `KS_DISPUTE_EVIDENCE_V1`;
- 64-character lowercase hex fact fingerprint;
- JSONB evidence sections must be an array with at least one element;
- unique `(order_id, schema_version, version)`;
- unique `(order_id, schema_version, fact_fingerprint)`;
- finalized state requires `finalized_at`, non-finalized states require null
  `finalized_at`;
- finalized snapshots cannot be updated.

PostgreSQL loads authoritative facts in a repeatable-read transaction and
serializes per-order draft persistence with an advisory transaction lock.

## Evidence Sections

Included from authoritative persisted facts:

- order status, payment status, procurement/fulfillment/risk/refund states,
  amount and currency;
- payment provider, masked provider reference, amount, currency, status and
  reconciliation metadata;
- customer account verification state and checkout-email match boolean;
- ownership binding metadata;
- guest claim success/active-count metadata;
- fraud decision, risk score, reason codes, review case status/resolution;
- velocity aggregates only, without subject keys;
- procurement status and masked supplier order reference;
- fulfillment status, retrieval/delivery states and boolean key-material
  retrieval metadata;
- delivery channel/status/reference-present metadata;
- invoice metadata when available, otherwise explicit `NOT_APPLICABLE`;
- allowlisted audit summary entries only.

Absent optional sources are explicitly represented and do not fabricate facts.

## Finalization and Export

- Finalization requires trusted `DisputeEvidenceFinalizationAuthorityPort`.
- Export requires trusted `DisputeEvidenceExportAuthorityPort`.
- Production defaults deny both actions.
- Finalized snapshots are immutable in PostgreSQL.
- Export requires exact snapshot and order binding.
- Audit is best-effort and metadata-only.
