## Migrations

Added reversible migration `006_catalog_search_operations`.

It creates `catalog_search_documents`, `catalog_operations`, deterministic search/filter indexes and a normal persisted PostgreSQL `tsvector` search document. No existing catalog, grouping, storefront, supplier, order or key-vault table is rewritten.

PR #11 hardening changed `search_text` from a generated column to an explicitly persisted `TSVECTOR NOT NULL` column, because PostgreSQL 16 rejects `to_tsvector(...)` in generated-column expressions as non-immutable. `PostgresCatalogSearchRepository` now builds a deterministic source string from canonical title, normalized title, product type, edition and stably sorted platforms, then writes `to_tsvector('simple', sourceText)` during insert/upsert.

## Search/Index Policy Version

`catalog-search-v1`

## Search Architecture

Search is implemented behind `CatalogSearchPort` and `CatalogSearchService`. The projection repository is separate from the canonical projection source so the search table remains reproducible from durable catalog state.

## Pagination Strategy

Search uses bounded cursor/keyset pagination with default limit `50` and maximum `200`. Invalid cursors fail with `CatalogSearchCursorError`.

## Event Flow

`CATALOG_PRODUCT_CHANGED` carries only `ProductId`, change categories, correlation ID, version and observed timestamp. It can refresh the search projection and request storefront re-evaluation when the change is material.

## Webhook Integration

Verified Kinguin `product.update` signals are modeled as refresh signals only. Invalid/unverified signals are rejected. Webhook metadata does not directly mutate WooCommerce and is not used as authoritative product truth.

## Storefront Integration

Material catalog changes can enqueue a reference-only storefront re-evaluation request. Storefront publication remains owned by KS-05-03 and can still return `NO_OP` when the fingerprint is unchanged.

## Reindex Behavior

Reindex reads canonical ProductIds in bounded batches, stores a durable checkpoint, records processed/changed/failed counts and can restart from the last ProductId. It requires no supplier API calls and no WooCommerce calls.

## 50k Scale Results

The focused unit suite rebuilds 50,000 deterministic synthetic search projections, performs exact lookup and runs a common paginated filtered text query. The local run completed under the broad 15-second regression budget.

Dedicated local measurement:

- full in-memory projection rebuild: 50,000 processed, 50,000 changed, 418 ms;
- exact lookup: 0.05 ms;
- common filtered paginated text query: 83.8 ms;
- incremental one-product refresh: 0.15 ms.
