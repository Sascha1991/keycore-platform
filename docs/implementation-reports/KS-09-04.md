## Architecture

KS-09-04 introduces internal `SupportCase` records with customer-owned order
support, account-only customer cases, trusted operator-created cases, structured
messages, internal notes, explicit status transitions, immutable ownership,
record versions and append-only history events.

The implementation is provider-neutral and does not bind to any helpdesk SaaS.
PostgreSQL is the durable source of truth. Redis is not used for support state.

## Security Boundaries

- Customer actions require an authenticated customer principal and persisted
  customer.
- Order-scoped customer cases require an order already owned by the principal.
- Wrong-owner, unknown and unclaimed orders return `RESOURCE_NOT_AVAILABLE`.
- Customer request authority fields are rejected.
- Operator actions require `SupportOperatorAuthorityPort`; the default
  authority fails closed.
- Customer-visible projections exclude internal notes.
- Support links are trusted-operator only and exact-order bound.
- Message bodies are excluded from audit metadata.

## Persistence

Migration 023 adds `support_cases`, `support_messages`,
`support_case_events` and `support_case_links`.

Database constraints enforce typed enums, immutable case ownership/source,
bounded safe message text, customer-visible customer messages, append-only
events and unique support links.
