## Security

## Known Documentation Ambiguities

- `POST /v2/order` examples show string `productId`, while one table labels the type as `int`; the adapter follows the examples and product v2 docs.
- Webhook verification is documented as shared secret headers only; no stronger signature algorithm is specified.
- `order.complete` is deprecated by Kinguin changelog but required by KS-04-01; the adapter classifies it only for compatibility.
- `orderExternalId` should be unique, but no full idempotency guarantee is documented; timeout and duplicate behavior remains reconciliation-bound.
- Numeric rate limits are not documented; HTTP `429` maps to `RATE_LIMIT` without invented limits.
- Durable `SupplierOfferId` to `SupplierProductId` mapping persistence is not implemented in KS-04-01. The adapter-local index is the foundation boundary; production catalog sync must seed or persist the mapping before real purchasing is enabled.
