## Official Documentation Re-Check

Reviewed the official Kinguin eCommerce API documentation for Order v2,
top-level API authentication/environments, quickstart safety notes and error
codes.

Verified findings:

- order creation remains `POST /v2/order`;
- the documented order request product fields include `productId`, `qty`,
  `price`, `keyType` and `offerId`;
- `orderExternalId` is a custom external reference and should be unique;
- key retrieval is documented separately as `GET /v2/order/{orderId}/keys` and
  remains forbidden for controlled procurement;
- API authentication uses the `X-Api-Key` header;
- documented non-2xx error payloads include machine fields such as `kind` and
  `status`, plus fields that may contain unsafe human/debug data such as
  `detail`, `trace`, `propertyPath` and `invalidValue`;
- documented error `kind` values include `ConstraintViolation`, `Error`,
  `HttpClient`, `Http`, `Authorization`, `InsufficientBalance`, `OrderFailed`,
  `Preorder`, `ProductUnavailable`, `OrderNotFound`, `ResourceLock`,
  `OrderNotSupported` and `NoKeysToReturn`.

## Implemented Behavior

Definitive controlled Kinguin order rejections now persist safe normalized
diagnostics:

- `supplierHttpStatus`;
- `supplierErrorCode`;
- `supplierErrorCategory`;
- `safeReasonCode`.

Only sanitized documented-style machine codes are retained. Raw response bodies,
supplier messages, headers, trace data, debug fields, API keys, execution tokens
and product-key material are not persisted or printed.

HTTP 4xx order-create responses are treated as definitive rejections and mapped
to safe categories. HTTP 5xx, timeouts, connection failures and malformed
possible-success responses remain `AMBIGUOUS`. No automatic retry or second
`POST /v2/order` is introduced.

Reconciliation returns persisted rejection diagnostics for confirmed historical
rejections when those fields exist. Older rejected approvals without diagnostics
remain readable and return no diagnostic fields.

Added a local database-only inspect command:

```sh
npm run kinguin:inspect-controlled-procurement -- <approvalId>
```

The command reads only the local KeyCore database and does not call Kinguin.

## Migration

Added reversible migration 013 for nullable rejection diagnostic fields on
`controlled_procurement_approvals`.

The migration enforces:

- HTTP status is null or `100..599`;
- supplier error code is null or bounded safe machine text;
- supplier error category is null or one of the approved enum values;
- safe rejection reason code is null or bounded uppercase safe machine text.

No raw response, header or supplier-message column was added.
