## Acceptance Criteria Status

- Trusted authentication assertion boundary: implemented via
  `CustomerAuthenticationAuthorityPort`.
- Provider-subject binding lookup: implemented through persisted
  `(provider, providerSubject)` identity bindings; no email-only auth and no
  request `customerId` trust.
- Server-side session table: implemented in migration 017.
- Opaque token generation: 32-byte base64url token, SHA-256 hash persisted only.
- Session creation, resolution, rotation, revoke and revoke-all: implemented.
- Idle timeout and touch interval: implemented with conditional touch updates.
- Session-backed `AuthenticatedCustomerPrincipal`: implemented with
  `AUTHENTICATED` assurance only.
- Safe inspect command: implemented.
- Cookie/transport policy: documented.
- PostgreSQL remains durable source of truth; no Redis or supplier state added.
- No production login provider, UI, email delivery, checkout, Stripe mutation,
  Kinguin procurement or key retrieval was implemented.
