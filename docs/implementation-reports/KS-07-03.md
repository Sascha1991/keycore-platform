## State Model

Procurement statuses: `PENDING`, `READY`, `IN_FLIGHT`, `SUCCEEDED`, `FAILED_RETRYABLE`, `FAILED_TERMINAL`, `AMBIGUOUS`, `RECONCILIATION_REQUIRED`.

Dispatch states: `NOT_DISPATCHED`, `DISPATCH_STARTED`, `DISPATCH_CONFIRMED`.

## Execution Ownership

Durable ownership uses `execution_token` and `execution_started_at`. Only the lease owner may dispatch supplier mutation and persist the outcome. Fresh leases return `PROCUREMENT_ALREADY_IN_FLIGHT`. Stale `DISPATCH_STARTED` work becomes ambiguous instead of being retried blindly.

## Behavior

- Eligibility requires captured payment, approved risk, quantity `1`, safe order state and no existing success/ambiguity.
- Profitability is revalidated immediately before mutation against the current supplier offer.
- Routing uses the existing supplier routing foundation.
- Dry run creates a safe would-be operation and performs zero supplier mutation calls.
- Success persists external supplier order ID, supplier identifiers, normalized supplier status, acquisition cost and response fingerprint.
- Retryable failures are limited to responses that are safe to retry for the same supplier.
- Terminal failures can preserve history and allow a future generation if fallback policy permits.
- Ambiguous outcomes block cross-supplier fallback and require reconciliation/manual review.
- Reconciliation uses known supplier order IDs only; no guessing by amount/product/timestamp.

## PR #16 CI Hardening

GitHub Actions Quality Gates #60 exposed two real PostgreSQL concurrency
defects in the first KS-07-03 implementation:

- concurrent `createNextAttempt` tests shared one `pg.Client`, causing
  overlapping `BEGIN`/`COMMIT` calls and allowing raw
  `procurement_operations_order_generation_idx` violations to surface;
- `acquireExecutionLease` selected and decided in JavaScript before updating,
  so concurrent callers could all observe the same eligible row and all
  return `ACQUIRED`.

The repository now uses one transaction-scoped advisory lock per `OrderId`
inside `createNextAttempt`, while the test harness opens a separate
`pg.Client` per concurrent actor in the same isolated schema. Lease acquisition
is now a single atomic conditional `UPDATE ... RETURNING` that can be won by
only one caller. Callers that lose inspect the current row and return controlled
states such as `IN_FLIGHT`, `STALE_DISPATCH_STARTED` or `NOT_ELIGIBLE`.

Stale `NOT_DISPATCHED` leases may be recovered by a new token. Stale
`DISPATCH_STARTED` leases cannot be reacquired for another supplier mutation;
they are routed to ambiguity/reconciliation. Result writes remain
`execution_token`-owned, so old workers cannot persist dispatch, success or
failure after ownership is lost.
