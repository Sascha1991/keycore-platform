# KS-07-03d Implementation Report

## Summary

Implemented controlled Kinguin candidate discovery pagination on branch
`feature/ks-07-03d-kinguin-candidate-pagination`.

The change is read-only. It does not alter controlled live purchase execution,
approval preparation, supplier order creation, key retrieval or customer
procurement semantics.

## Scope

Added bounded pagination for:

- `ControlledLiveProcurementService.listCandidates`;
- `npm run kinguin:list-live-test-candidates`.

The CLI accepts:

- `--page-size <n>` default `20`, hard cap `20`;
- `--max-pages <n>` default `10`, hard cap `25`;
- `--max-candidates <n>` default `10`, hard cap `20`;
- `--start-page <n>` default `1`.

Invalid zero, negative, malformed or unsafe integer CLI values are rejected.
Values above service caps are bounded by the service and cannot create an
unbounded crawl.

## Pagination Design

Candidate discovery requests Kinguin product pages with:

`GET /v1/products?page=<page>&limit=<page-size>`

For each returned product record, it fetches product details through:

`GET /v2/products/{productId}`

The detail request exposes normalized offer data needed for the existing
Germany eligibility, availability and price filters. The read-only transport
guard still enforces GET-only behavior and blocks order mutation and key paths.

The search stops when:

- `maxCandidates` eligible candidates have been found;
- the API indicates the end of results;
- an empty page is returned;
- `maxPages` has been reached.

The implementation does not request duplicate product pages.

## Candidate Safety

Existing filters remain in place:

- Germany eligibility must be allowed;
- unknown regions remain excluded;
- unavailable or unknown availability remains excluded;
- known conflicting SupplierOfferId to SupplierProductId mappings are excluded;
- acquisition price must be positive;
- currency must be EUR;
- quantity policy remains unchanged.

Candidates are deduplicated by supplier, SupplierProductId and SupplierOfferId.
Sorting uses BigInt numeric minor-unit comparison, then SupplierProductId, then
SupplierOfferId for deterministic tie-breaking.

## Output

Safe JSON output now includes:

- `pagesInspected`;
- `productRecordsInspected`;
- `eligibleCandidatesFound`;
- `searchStoppedBecause`;
- `candidates`;
- `endpointsTested`;
- `mutationRequestCount: 0`.

`productRecordsInspected` counts real records processed from returned pages, not
`pageSize * maxPages`.

No API key, raw `X-Api-Key` header, raw supplier payload, product key, customer
data or approval token is emitted.
